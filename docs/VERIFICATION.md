## 视觉与评审

选定方向为白底、石墨文字、青绿色交互的轻量工具面板，突出当前网站和可编辑规则。未使用插画，参数和状态本身是内容主角。

两轮独立静态视觉评审，评分分别为 **8/10、8/10**。首轮提出品牌占位、编辑入口可发现性、底栏边缘和重复空状态入口问题；已压缩品牌行、加入铅笔按钮、固定底栏与滚动区域、增加列表末尾留白、删除重复入口。第二轮无必须修改的可见问题，提出图标对比度可提升；最终已加深操作图标。

动效包括首次出场、开关、标签下划线、编辑面板和保存提示。工具检测到首次进入和编辑转场，并生成录像；主 Agent 查看了关键帧并实际走查状态，评审者无法完整播放录像，因此评分仅针对静态视觉，不宣称录像已被完整观看或有实测帧率。

减法：删除空状态中央重复的「添加规则」操作，将泛化说明缩为一行；两种 Cookie 的能力边界说明保留，因为会改变用户对实际写入行为的理解。

## 原生工具栏弹窗修复

用户发现实际工具栏弹窗被挤成窄条。旧版端到端测试把扩展页面当标签页并强制设为 480×600，未覆盖 Chrome 自动测量 action popup 的过程。窄屏样式中的 `width: 100vw` 会将初始小视口宽度反馈到内容尺寸，造成收缩循环。

修复为原生扩展文档设置明确的 480px 宽度和最小宽度；网页预览的媒体查询仅作用于 preview surface。原生弹窗内容高度取可用视口与 600px 的较小值，保持底栏可见；文档固有尺寸保持独立，避免高度反馈收缩。

新增 `npm run test:popup`，通过 `chrome.action.openPopup()` 打开真实原生弹窗，不设置 popup 的设备或视口模拟。覆盖正常窗口、较矮窗口、再次打开，并分别检查列表与编辑态的宽度及底栏可见性。证据在 `evidence/native-popup/`。

本次修复后：类型检查通过；三次原生 action popup 打开及编辑态检查通过；既有 10 项逻辑测试与 16 项浏览器检查再次连续三轮通过。隔离浏览器可用屏幕限制下，实际弹窗视口为 495×498，内容固有宽度 480px，底栏位于可用高度内，未模拟 popup 视口。
